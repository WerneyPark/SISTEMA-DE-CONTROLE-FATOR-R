1 Visão Geral & Problema de Negócio

O Sistema de Controle Fator R é uma solução corporativa full-stack desenvolvida para automação tributária e planejamento fiscal de empresas prestadoras de serviços enquadradas no Simples Nacional (conforme a Lei Complementar nº 123/2006 e resoluções do CGSN).

🎯 Problema Resolvido

Diversas atividades intelectuais e de serviços (como desenvolvimento de software, consultoria em TI, clínicas médicas, engenharia e arquitetura) são legalmente sujeitas ao mecanismo do Fator R. Se a proporção da folha salarial for igual ou superior a 28% do faturamento dos últimos 12 meses, a empresa é tributada pelo Anexo III (alíquotas iniciais de 6,00%). Caso contrário, é tributada pelo Anexo V (alíquotas iniciais de 15,50%).

💡 Solução da Plataforma

O sistema calcula em tempo real o Fator R de cada competência, aplica a proporcionalização de RBT12 para empresas com menos de 12 meses de atividade, calcula a alíquota efetiva do Simples Nacional, compara com o regime de Lucro Presumido, gera alertas antecipados de proximidade de margem e simula cenários futuros de faturamento (+15%, neutro e -15%).

2 Arquitetura e Padrão de Design

A plataforma é construída sob uma arquitetura desacoplada e desacoplável, estruturada em três camadas essenciais:

SPA Client (Frontend)

Angular 21 Standalone

RxJS State / Forms / Chart / SCSS
⟷ HTTP / JSON REST ⟷

API Backend Server

Java 21 + Spring Boot 4.0.6

Spring WebMVC / Spring Data JPA / Validation
⟷ JDBC / SQL ⟷

Banco de Dados Relacional

PostgreSQL 16

Docker Container

Padrões de Projeto (Design Patterns) Utilizados

Layered Architecture (Camadas)

Separação estrita de responsabilidades: Controller (comunicação HTTP/JSON), Service (regras tributárias e cálculos), Repository (acesso a dados com Spring Data) e Domain Entity (mapeamento ORM Hibernate).

DTO (Data Transfer Object)

Isolamento das entidades do banco de dados na comunicação externa, garantindo segurança de tipos, controle de serialização e proteção contra *Overposting*.

Repository Pattern & Dependency Injection

Inversão de controle via @Autowired e injeção por construtor com @RequiredArgsConstructor (Lombok), desacoplando a persistência.

Reactive State & Context Sharing

No frontend, uso de BehaviorSubject do RxJS no EmpresaContextService e AuthService para prover estado global reativo da empresa selecionada e do usuário autenticado.

4 Fórmulas Matemáticas e Regras Fiscais

Abaixo estão descritas todas as regras matemáticas e fiscais implementadas no núcleo do sistema:

1. Cálculo do Percentual do Fator R

O Fator R é obtido dividindo a soma da folha de pagamento dos 12 meses anteriores à competência pela soma da receita bruta acumulada no mesmo período:

Fator R = ( Σ Folha de Pagamento nos últimos 12 meses ) ÷ ( Σ Receita Bruta nos últimos 12 meses )

Regra de Enquadramento:

  • Se Fator R ≥ 0.28 (28%) → Tributação pelo Anexo III (Alíquota menor, mais vantajoso).
  • Se Fator R < 0.28 (28%) → Tributação pelo Anexo V (Alíquota maior).
  • Caso especial de Faturamento Zero: Se Σ Receita Bruta = 0, para evitar divisão por zero (ArithmeticException), o sistema enquadra automaticamente no Anexo V com percentual 0,00%.

2. Regra dos Alertas de Proximidade da Margem

O sistema monitora faixas críticas de transição entre os Anexos III e V:

  • Zona de Oportunidade (25,00% a 27,99%): Dispara alerta informando que um pequeno aumento na folha de pagamento (ex: retirada de pró-labore adicional) pode migrar a empresa para o Anexo III, gerando grande economia tributária.
  • Zona de Risco de Rebaixamento (28,00% a 31,00%): Dispara alerta informando que a empresa está operando próxima do limite e qualquer redução na folha pode rebaixá-la de volta ao oneroso Anexo V.

3. Proporcionalização do RBT12 (Início de Atividade < 12 meses)

Para empresas com menos de 12 meses completos de operação desde a dataInicioAtividade, a Receita Bruta Total acumulada não reflete o ano cheio. O sistema efetua a proporcionalização regulamentar pela média mensal multiplicada por 12:

RBT12 Proporcional = ( Σ Faturamento nos meses de atividade ÷ Meses de Atividade ) × 12

4. Cálculo da Alíquota Efetiva do Simples Nacional

Diferente da alíquota nominal de tabela, a alíquota efetivamente cobrada no DAS considera a dedução da faixa:

Alíquota Efetiva SN = [ ( RBT12 × Alíquota Nominal ) - Parcela a Deduzir ] ÷ RBT12

O imposto mensal estimado para a competência é dado por: Valor SN = Faturamento do Mês × Alíquota Efetiva SN.

Regra Especial da 6ª Faixa: Quando o RBT12 ultrapassa R$ 3.600.000,00 (atingindo a Faixa 6), o sistema exibe aviso formal de que o ICMS e ISS ultrapassaram o sublimite estadual e devem ser recolhidos em guias municipais e estaduais separadas, fora do DAS.

5. Apuração Comparativa no Lucro Presumido (Serviços)

Para determinar o regime mais vantajoso, o sistema calcula todos os tributos federais e municipais incidentes no Lucro Presumido:

Tributo Base de Cálculo Alíquota Aplicada Fórmula
PIS Faturamento do Mês 0,65% Fat × 0,0065
COFINS Faturamento do Mês 3,00% Fat × 0,0300
ISS Faturamento do Mês 5,00% Fat × 0,0500
Base Presumida IRPJ/CSLL Faturamento do Mês 32,00% (Presunção Serviços) Base = Fat × 0,32
IRPJ Base Presumida 15,00% Base × 0,1500
CSLL Base Presumida 9,00% Base × 0,0900
Adicional IRPJ Base Presumida que exceder R$ 20.000,00/mês 10,00% (Base - 20.000) × 0,10
Valor Total Lucro Presumido = PIS + COFINS + ISS + IRPJ + CSLL + Adicional IRPJ

Economia Estimada: | Valor LP - Valor SN |. O sistema define regimeMaisVantajoso comparando diretamente os valores devidos.

6 Algoritmo de Projeção de Cenários Futuros

O sistema implementa o algoritmo de Janela Deslizante de 12 Meses para projetar o impacto fiscal dos próximos dois meses subsequentes (M+1 e M+2) em três cenários:

📈 Cenário Otimista (+15%)

Multiplica a receita base por 1.15 e mantém a folha salarial atual.

⚖️ Cenário Neutro (0%)

Mantém a receita e a folha do mês atual com multiplicador 1.00.

📉 Cenário Pessimista (-15%)

Aplica multiplicador de 0.85 na receita mantendo a folha fixa.

Lógica da Janela Deslizante

Para calcular o RBT12 do mês M+1:

RBT12(M+1) = RBT12_Atual - Faturamento(M-12) + FaturamentoProjetado(M+1)

Para calcular o RBT12 do mês M+2:

RBT12(M+2) = RBT12(M+1) - Faturamento(M-11) + FaturamentoProjetado(M+2)

7 Backend: Entidades de Domínio (JPA)

Mapeamento relacional ORM das tabelas do banco de dados PostgreSQL:

com.fatorr.backend.domain.Empresa

Representa a entidade principal do cliente corporativo ou pessoa jurídica.

  • id: Long - Chave primária auto-incremental (@Id @GeneratedValue).
  • razaoSocial: String - Nome empresarial registrado (obrigatório).
  • cnpj: String - CNPJ único indexado (@Column(unique = true)).
  • dataInicioAtividade: LocalDate - Data de abertura para cálculo de proporcionalidade.
  • usuarios: Set<Usuario> - Relação ManyToMany com usuários autorizados.
  • faturamentos: List<FaturamentoMensal> - Lista de receitas registradas (Cascade ALL).
  • folhas: List<FolhaPagamentoMensal> - Lista de folhas registradas (Cascade ALL).
  • parametros: List<ParametroTributario> - Parâmetros tributários específicos da empresa.

com.fatorr.backend.domain.FaixaTributaria

Representa uma linha da tabela progressiva dos Anexos do Simples Nacional.

  • id: Long - Chave primária.
  • anexo: String - Identificador do Anexo ("III" ou "V").
  • numeroFaixa: Integer - Número ordinal da faixa (1 a 6).
  • limiteSuperior: BigDecimal - Teto de RBT12 (nulo para faixa 6).
  • aliquotaNominal: BigDecimal - Alíquota percentual da faixa (ex: 0.0600).
  • valorDeduzir: BigDecimal - Parcela a deduzir em Reais (ex: 9360.00).
  • parametro: ParametroTributario - Relação ManyToOne com a tabela pai.

com.fatorr.backend.domain.FaturamentoMensal

Registro do faturamento bruto recebido em determinada competência mensal.

  • id: Long - Chave primária.
  • empresa: Empresa - Empresa dona do lançamento (ManyToOne).
  • competencia: YearMonth - Mês e ano da competência (ex: 2026-05).
  • valor: BigDecimal - Valor total faturado no mês.

com.fatorr.backend.domain.FolhaPagamentoMensal

Registro do total de gastos com folha de pagamento, salários e pró-labore no mês.

  • id: Long - Chave primária.
  • empresa: Empresa - Empresa proprietária da folha.
  • competencia: YearMonth - Ano e mês da folha.
  • valor: BigDecimal - Montante total pago em folha.

com.fatorr.backend.domain.ParametroTributario

Configurações de alíquotas do Lucro Presumido e coleção de faixas progressivas.

  • id: Long - Chave primária.
  • aliquotaPis, aliquotaCofins, aliquotaIss, aliquotaIrpj, aliquotaAdicionalIrpj, aliquotaCsll: BigDecimal - Alíquotas de tributos federais e municipais do Lucro Presumido.
  • ativo: boolean - Flag indicador de configuração ativa.
  • empresa: Empresa - Referência à empresa (nulo para padrão global do sistema).
  • faixas: List<FaixaTributaria> - Coleção Eager das faixas de Anexo III e V.

com.fatorr.backend.domain.Usuario & TipoUsuario

Entidade de controle de acesso e perfil de usuário.

  • id: Long - Identificador único.
  • cpf: String - CPF do usuário (chave de login única).
  • senha: String - Senha de autenticação (@JsonIgnore).
  • tipo: TipoUsuario - ADMINISTRADOR_CONTABIL ou USUARIO_EMPRESA.
  • empresas: Set<Empresa> - Conjunto de empresas às quais o usuário tem permissão de acesso.

10 Backend: Serviços e Métodos Detalhados

Especificação exaustiva de cada método existente na camada de serviços:

CalculoFatorRService

getParametros(Long empresaId) private

Objetivo: Recupera os parâmetros tributários ativos da empresa, aplicando fallback para os parâmetros globais e fallback em memória caso o banco esteja vazio.

  • Parâmetros: Long empresaId (ID da empresa consultada).
  • Retorno: ParametroTributario (objeto com alíquotas e faixas).
  • Exceções: Nenhuma.
calcularFatorR(Long empresaId, YearMonth competenciaReferencia) public

Objetivo: Realiza a apuração do Fator R da empresa para a competência indicada com base nos 12 meses anteriores.

  • Parâmetros: Long empresaId (ID da empresa), YearMonth competenciaReferencia (Mês e ano da apuração).
  • Retorno: FatorRResultadoDTO (DTO com totais de faturamento e folha, percentual apurado e enquadramento em Anexo III ou V).
  • Exceções: Dispara IllegalArgumentException se a empresa não existir.
simularTributacao(Long empresaId, YearMonth competenciaReferencia) public

Objetivo: Executa a simulação fiscal completa: Fator R, alertas de margem, proporcionalização de RBT12, busca de faixa progressiva, cálculo de alíquota efetiva do Simples Nacional, apuração de todos os tributos do Lucro Presumido e cálculo de economia.

  • Parâmetros: Long empresaId, YearMonth competenciaReferencia.
  • Retorno: SimulacaoTributariaDTO (Payload detalhado com comparativo de regimes e histórico).
  • Exceções: Dispara IllegalArgumentException se o ID da empresa for inválido.
simularProximosMeses(Long empresaId, YearMonth competenciaReferencia) public

Objetivo: Gera a projeção dos meses M+1 e M+2 para três cenários hipotéticos (Otimista +15%, Neutro 0% e Pessimista -15%).

  • Parâmetros: Long empresaId, YearMonth competenciaReferencia.
  • Retorno: List<ProjecaoCenarioDTO> contendo os 3 cenários e seus respectivos meses projetados.
  • Exceções: Propaga IllegalArgumentException se a empresa não existir.
gerarCenario(Long empresaId, YearMonth competenciaAtual, SimulacaoTributariaDTO simulacaoAtual, BigDecimal faturamentoBase, BigDecimal folhaBase, String nome, String descricao, BigDecimal multiplicador) private

Objetivo: Constrói um cenário de projeção específico aplicando a janela deslizante de 12 meses e calculando os impostos projetados.

  • Parâmetros: Dados de contexto da simulação atual e o multiplicador de faturamento (1.15, 1.00 ou 0.85).
  • Retorno: ProjecaoCenarioDTO com a lista de meses calculados.
  • Exceções: Nenhuma.
calcularMesProjecao(YearMonth competencia, BigDecimal faturamentoEstimado, BigDecimal folhaEstimada, BigDecimal rbt12Estimado, BigDecimal folha12Estimado, ParametroTributario params) private

Objetivo: Calcula a alíquota efetiva e o imposto estimado no Simples Nacional para um mês individualizado de projeção.

  • Parâmetros: Competência futura, valores estimados de faturamento/folha e parâmetros tributários.
  • Retorno: ProjecaoCenarioDTO.MesProjecaoDTO.
  • Exceções: Nenhuma.

  • Exceções: Dispara UnsupportedOperationException (módulo preparado para integração com Jackson XML / JAXB).
processarLote(MultipartFile[] arquivos) public

Objetivo: Itera sobre um lote de múltiplos arquivos XML enviados via upload para processamento em massa.

  • Parâmetros: MultipartFile[] arquivos.
  • Retorno: void.
  • Exceções: Dispara UnsupportedOperationException.

11 Backend: Controllers e Endpoints REST

Detalhamento de todos os controladores da camada WebMVC:

AuthController (Base: /api/auth)

POST /login login(@RequestBody LoginDTO loginDto)

Recebe CPF e senha, valida as credenciais no banco e retorna AuthResponseDTO (Status 200 OK) ou Status 401 UNAUTHORIZED caso as credenciais estejam inválidas.

EmpresaController (Base: /api/empresas)

GET / listarTodas(@RequestParam(required = false) Long usuarioId)

Lista todas as empresas do sistema ou filtra apenas as empresas associadas ao usuarioId informado.

GET /{id} buscarPorId(@PathVariable Long id)

Retorna a empresa com o ID especificado ou 404 NOT FOUND se não existir.

POST / criar(@RequestBody Empresa empresa)

Cadastra e persiste uma nova empresa no banco de dados.

PUT /{id} atualizar(@PathVariable Long id, @RequestBody Empresa empresaAtualizada)

Atualiza a Razão Social e o CNPJ de uma empresa existente.

DELETE /{id} excluir(@PathVariable Long id)

Remove a empresa e todos os seus lançamentos associados (Cascade ALL). Retorna 204 NO CONTENT.

GET /{id}/simulacao-tributaria simularTributacao(@PathVariable Long id, @RequestParam(required = false) Integer ano, @RequestParam(required = false) Integer mes)

Calcula a simulação tributária completa para o ano/mês especificados (ou mês atual se omitido).

GET /{id}/simulacao-futura simularProximosMeses(@PathVariable Long id, @RequestParam(required = false) Integer ano, @RequestParam(required = false) Integer mes)

Calcula os 3 cenários de projeção futura para as duas competências seguintes.

FaturamentoMensalController (Base: /api/faturamentos)

POST / criar(@RequestBody FaturamentoMensalDTO dto)

Cria ou sobrescreve de forma idempotente o faturamento da competência para a empresa informada.

GET /empresa/{empresaId} listarPorEmpresa(@PathVariable Long empresaId)

Retorna os registros de faturamento dos últimos 12 meses da empresa.

DELETE /{id} excluir(@PathVariable Long id)

Exclui um lançamento de faturamento por ID.

FolhaPagamentoMensalController (Base: /api/folhas)

POST / criar(@RequestBody FolhaPagamentoMensalDTO dto)

Cria ou sobrescreve a folha de pagamento da competência indicada para a empresa.

GET /empresa/{empresaId} listarPorEmpresa(@PathVariable Long empresaId)

Retorna os registros de folha dos últimos 12 meses da empresa.

DELETE /{id} excluir(@PathVariable Long id)

Exclui um lançamento de folha por ID.

ParametroTributarioController (Base: /api/parametros)

GET /padrao getPadrao()

Retorna os parâmetros tributários e faixas padrão globais do sistema.

POST /padrao salvarPadrao(@RequestBody ParametroTributario novoParametro)

Desativa o padrão atual e grava uma nova versão das alíquotas e faixas padrão globais.

GET /empresa/{empresaId} getPorEmpresa(@PathVariable Long empresaId)

Retorna a configuração de alíquotas e faixas customizadas para uma empresa.

POST /empresa/{empresaId} salvarPorEmpresa(@PathVariable Long empresaId, @RequestBody ParametroTributario novoParametro)

Grava alíquotas e faixas customizadas exclusivamente para a empresa indicada.

GET /atual getAtual()

Endpoint de compatibilidade que redireciona internamente para getPadrao().

UsuarioController (Base: /api/usuarios)

POST /vincular-empresa criarEVincularUsuario(@RequestBody NovoUsuarioEmpresaDTO dto)

Cria um novo usuário cliente ou atualiza a senha de usuário existente e o vincula à empresa indicada.

GET / listarTodosUsuarios()

Retorna a lista completa de usuários do sistema com resumo das empresas associadas.

GET /empresa/{empresaId} listarUsuariosDaEmpresa(@PathVariable Long empresaId)

Retorna todos os usuários que têm permissão de acesso à empresa indicada.

DELETE /{usuarioId}/vincular-empresa/{empresaId} desvincularUsuario(@PathVariable Long usuarioId, @PathVariable Long empresaId)

Remove a permissão de acesso do usuário à empresa indicada.

13 Frontend: Serviços & Gerenciamento de Estado

Serviços injetáveis do Angular gerenciando requisições HTTP e estado reativo com RxJS:

AuthService

  • currentUser$: Observable reativo do usuário atualmente autenticado.
  • login(cpf: string, senha: string): Executa POST em /api/auth/login, salva os dados no localStorage e emite no BehaviorSubject.
  • logout(): Limpa o localStorage e emite null no BehaviorSubject.
  • getCurrentUser(): Retorna o AuthResponse síncrono.
  • isLoggedIn(): Retorna boolean indicando se há usuário logado.
  • isAdmin(): Retorna true se o perfil for ADMINISTRADOR_CONTABIL.

EmpresaContextService

  • empresaSelecionada$: Observable reativo da empresa atualmente ativa em toda a interface.
  • empresas$: Observable com a lista completa de empresas carregadas.
  • setEmpresas(empresas: Empresa[]): Atualiza a lista e sincroniza a empresa selecionada com persistência no localStorage.
  • setEmpresaSelecionada(empresa: Empresa | null): Define e persiste a empresa ativa.
  • getEmpresaSelecionada(): Retorna a empresa ativa atual.

FatorRService

  • simularTributacao(empresaId, ano, mes): Chama GET /api/empresas/{id}/simulacao-tributaria.
  • simularFuturo(empresaId, ano, mes): Chama GET /api/empresas/{id}/simulacao-futura.
  • listarFaturamentos(empresaId): Chama GET /api/faturamentos/empresa/{id}.
  • criarFaturamento(dto): Chama POST /api/faturamentos.
  • excluirFaturamento(id): Chama DELETE /api/faturamentos/{id}.
  • listarFolhas(empresaId): Chama GET /api/folhas/empresa/{id}.
  • criarFolha(dto): Chama POST /api/folhas.
  • excluirFolha(id): Chama DELETE /api/folhas/{id}.
  • obterParametrosPadrao() / salvarParametrosPadrao(dto): Gerenciamento dos parâmetros padrão globais.
  • obterParametrosPorEmpresa(id) / salvarParametrosPorEmpresa(id, dto): Gerenciamento dos parâmetros da empresa.

UsuarioService

  • vincularEmpresa(dto: NovoUsuarioEmpresaDTO): Chama POST /api/usuarios/vincular-empresa.
  • listarPorEmpresa(empresaId: number): Chama GET /api/usuarios/empresa/{empresaId}.
  • listarTodos(): Chama GET /api/usuarios.
  • desvincularEmpresa(usuarioId, empresaId): Chama DELETE /api/usuarios/{usuarioId}/vincular-empresa/{empresaId}.

17 Guia de Instalação e Execução Passo a Passo

Passo 1: Subir o PostgreSQL via Docker

docker-compose up -d

Passo 2: Iniciar a API Backend (Spring Boot)

cd backend
# Windows
.\mvnw.cmd spring-boot:run
# Linux / macOS
./mvnw spring-boot:run

O backend inicializará na porta 8080 e criará automaticamente as tabelas e o usuário administrador padrão (CPF: 00000000000 / Senha: admin123).

Passo 3: Iniciar a Aplicação Frontend (Angular)

cd frontend
npm install
npm start

Acesse a interface no navegador em: http://localhost:4200.
